## 二、总体判断

1. 执行卡这条线是可靠的。取数、两源核价、计算、按时推送、可复现，这五件事今天都经得起核查。实盘仍然只有三条卖出规则（C级清退、单票归位、熔断），执行卡上能看到的结论都可以追到账本和收盘价。
2. 驾驶舱这条线有实质问题。问题不在计算引擎，而在三处：
   - 代码里手写的数字已经过时；
   - 生产运行不归档，"今日变化"拿去对比的是一份旧口径的快照；
   - 研究数据停在一季报，页面上又不写明是哪一期。

   结果是同一页上出现互相矛盾的数字。由于研究层不进执行卡，这些问题不影响今天的交易指令，但会误导人看页面时的判断。
3. 有两条规则和展示之间逻辑不通，需要裁定：
   - 执行债务的口径与执行卡的三条规则不一致；
   - "资金核验"闸门按设计永远无法通过。
4. 有一项公开范围问题，比任何显示问题都重要：仓库和 GitHub Pages 上的执行卡、账本文件都含绝对金额，现金精确到分。

## 四、做对了、应当保留的部分

- 执行卡的结论可以从账本股数和收盘价独立复算，复算结果一致。
- 两源核价（腾讯 / 新浪），任何一只不一致就不出结论。
- 冻结指纹 `fbd2c753e958`（51 条规则）每次运行都核对，未漂移。
- 研究隔离与无动作检查（39 项全链路审计）由程序机械执行。
- "缺失"与"裁定排除"分开显示（如家庭安全垫）。
- 运行日志记录计划与实际时刻，漏跑可以被发现。

这些是整套程序的骨架，优化方案只在它们外面加东西，不动它们。

## 五、优化方案

### 5.1 架构：五层，单向流动

```text
采集层  →  账本层  →  规则层  →  研究 / 模拟层  →  发布层  →  呈现层
原始取数    已确认事实   三条实盘规则    只观察          统一打包       只读展示
带取数日志  带裁定出处   冻结指纹        不进执行卡      依据信封       不再计算
```

每一层的约束：

| 层 | 只做 | 不做 |
|---|---|---|
| 采集 | 取数、记录取数时刻与接口、两源比对、写原始文件 | 不判断 |
| 账本 | 股数、现金、峰值、债务、裁定。每个字段写来源与日期 | 不手写派生数字（市值、边界、缺口一律由程序算） |
| 规则 | C级清退、单票归位、熔断；冻结指纹 | 不读研究层和模拟层的结论 |
| 研究 / 模拟 | 观察、检验、记录假设 | 不写金额；不引用账本中的具体数字，只引用字段 |
| 发布 | 打包、哈希、清单、依据信封、新鲜度、金额剔除 | 不改任何数值 |
| 呈现 | 原样展示发布包 | 不重新计算，避免页面和执行卡出现两套数字 |

### 5.2 规则：先裁定，再写进程序

不新增规则，只把现有规则的边界写清楚：

1. 实盘动作只来自三条规则。执行债务里不属于这三条的，要么裁定纳入，要么移出（L1）。
2. 每个闸门都必须能回答"在什么数据下可以通过"。答不出来的，标"不可判定"，不参与"差几项"的计数（L2）。
3. 跨期对比的前提是口径相同；口径版本写进每一份快照（L3）。
4. 金额类数字只允许出现在账本层与私有产物中（P1–P3，待裁定）。

### 5.3 运算：数据怎么取、怎么算、怎么保证及时正确

| 措施 | 解决 | 做法 |
|---|---|---|
| 数据新鲜度登记 | S1–S5 | 每个数据集登记预期频率（行情每日、财报按披露截止日、资金雷达每日）；超期在页面变色，在发布清单里标出 |
| 财报自动重取 | S1、S2 | 4/30、8/31、10/31 之后第一个交易日自动重取，并记录最新报告期；10/31 三季报是第一个落地时点 |
| 生产归档 | E3、S7 | 盘后执行卡流程归档当日快照并提交回 git；只有这一处归档 |
| 口径版本 | L3 | 快照写入分母口径、峰值口径、规则指纹；变化栏先比口径再比数值 |
| 债务由台账计算 | S4、L1 | 台账每条有状态与凭证；`pendingSells` 改为由台账算出 |
| 禁止手写派生数字 | E1、E2、E4 | 审计新增一项：研究层与驾驶舱源码中不得出现"数字 + 万"的金额字面量；历史记录放在带日期的登记文件里 |
| 双重复算 | 保持 | 每日盘后由独立脚本按账本 × 收盘价复算执行卡核心百分比，与执行卡比对，不一致就告警（本次核查脚本可直接改成这一项） |

### 5.4 呈现：展示什么、怎么证明展示对

1. 执行卡是唯一的动作结论。驾驶舱首屏直接引用执行卡，不再自己写一套结论。
2. 每个数字带依据信封（来源、取数时刻、报告期、算法、代码位置、状态）。姊妹文档第六节有完整结构。
3. 过期、缺失、口径变化三种状态都有固定标识，不和正常读数混在一起。
4. 研究层与模拟层每个区块标题下只写一次"只观察，不进执行卡"。
5. 发布前做"页面对账"：从发布包中抽取仪表盘、执行卡、看台三处的同名数字（总资产比例、股票比例、现金比例、回撤），三处不一致就不发布。E1 这类问题以后会被机器拦下。
