## 一、总判断：按功能分层验收，不整体判定

平台不简单判为"可靠"或"不可靠"，按层分别给出状态：

| 层 | 当前状态 | 依据 | 可以用来做什么 | 不能用来做什么 |
|---|---|---|---|---|
| 执行层 | 有真实数据核验支持 | 生产代码重跑结果与已发布执行卡逐字节一致；按账本股数 × 收盘价独立复算，支持当日"无卖出" | 每日执行卡 | 不因此推定其他层可靠 |
| 研究层 | 存在明显滞后 | 财报停在一季报，资金雷达停在 9/29，历史快照只有三天 | 记录、复核线索 | 暂不用来判断 AI 基建周期拐点 |
| 驾驶舱 | 不是统一事实来源 | 同页存在过时金额、口径不一致、错误的变化提示 | 浏览研究材料 | 不作为任何数字的权威来源；数字以执行卡为准 |
| 规则层 | 待裁定后修改 | 执行债务口径与三条实盘规则不一致；"资金核验"闸门不可能通过 | 维持现行三条规则 | 不据此恢复或新增卖出指令 |

执行卡的可靠性不代表研究层具备可靠的趋势判断能力。财报更新、资金雷达、历史归档、数据口径全部修正，并通过研究层实际数据质量验收之后，才能用系统输出判断 AI 基建周期是在强化、放缓还是转折。

## 二、五项裁定

### 第 1 项　公开范围：敏感数据与公开展示分离（最高优先级）

裁定：

1. 权威账本、成本、股数、交易记录移入私有存储。公开页面只发布经审查的必要信息，即比例、状态、数据日期。
2. 不能只删除当前文件。已经进入公开 Git 历史的内容仍可被访问，也可能已有外部副本。顺序是：先控制当前访问，再评估历史清理。
3. 采取措施前，先核实仓库改私有对 Pages 和生产流程的影响（见第三节）。
4. 分离方案确认前，不再向公开仓库提交新的精确财务数据。

### 第 2 项　新易盛状态类卖出：不作为有效执行指令

裁定：

1. 状态类卖出不属于现行三类可生成卖单的规则（C级清退、单票归位、熔断），不能凭驾驶舱中的旧状态或提醒恢复为实盘指令。
2. 保留研究与复核记录；不进入每日执行卡；不改变现有持仓。
3. 如果将来要把它变成卖出规则，必须先明确触发条件、权限、模拟验证，并经正式批准。

实施后的效果：执行债务中不再把该条计为"未执行的卖出指令"。

### 第 3 项　资金核验闸门：标记"不可判定"，不永久封死

裁定：

1. 闸门采用三个独立状态：通过、未通过、不可判定。
2. 没有可用数据源，就不能要求闸门通过，也不能把缺数据解释成风险解除。
3. 代理变量可以进入研究层，但不能冒充真实资金数据。
4. 购买数据源之后也必须先经质量验证，不能自动取得"通过"资格。
5. 该闸门状态与生产买入权限分开管理。买入权限仍按既有冻结条件关闭，不因本裁定开启。

### 第 4 项　资金雷达：恢复每日运行，严格限定为研究用途

裁定：

1. 生产验收通过后，恢复每日定时采集与归档；验收前不修改现有生产分支。
2. 每次输出必须标明采集时间、数据日期、数据源、缺失项、是否过期。
3. 采集失败或数据过期时明确告警，不沿用旧数字伪装成当日数据。
4. 雷达只提供证据、触发复核。不改变名单层级，不开放建仓，不生成卖单。

### 第 5 项　驾驶舱首屏：改为引用统一生成结果

裁定：

1. 首屏不再手写金额，不自行计算，不独立维护口头约数。
2. 所有同名数字来自同一份带日期、带口径版本的生成结果。口径不一致时显示"不可直接比较"，不把口径变化显示为持仓变化。
3. 必须与第 1 项一起实施：内部权威数据可以含精确金额，公开展示仍须脱敏。不能为了统一数据源，把敏感账本原样暴露到公开页面。

## 三、第 1 项的影响核实（10/19 06:00 前完成，只读）

### 3.1 暴露范围

| 项 | 核实结果 |
|---|---|
| 仓库可见性 | 公开（public），个人账户所有，创建于 2025-10-29 |
| GitHub 上可见的扩散 | 分叉 0、星标 0、关注 0。这只说明 GitHub 上没有可见副本，不能排除外部克隆、抓取或缓存 |
| 账本文件历史 | `backend/src/services/cockpit/data/portfolio.json` 自 2026-08-13 起有 10 次提交，每一版都在公开历史中 |
| 分支 | 远端 36 个分支，全部公开，多数含账本与金额 |
| 含金额的位置 | 不止账本：`share/decision/` 17 个文件、`backend/src/` 约 32 个源文件（手写金额与注释）、`share/ladder/`、`战略组合2026-2030/` 下的账户快照日志、持仓评估、复盘、执行计划等文档 |
| 每日新增 | 每轮生产运行都把执行卡提交回公开分支。执行卡写出总资产与峰值（精确到百元）；有卖出时还写出股数、参考价、金额与卖后股数 |
| Pages | `cockpit.html` 含总资产、股票市值、现金等金额；执行卡页同上 |

结论：暴露是系统性的，不是一个文件的问题。只删除账本文件不能控制暴露。

### 3.2 仓库改私有的影响

| 影响面 | 结果 | 依据 |
|---|---|---|
| GitHub Pages | 个人账户在免费方案下，私有仓库不能发布 Pages，改私有后站点会下线；付费方案下可以继续发布，但站点本身仍对公网公开（Pages 访问控制只在企业版提供）。也就是说，改私有不能让 Pages 上的金额消失，Pages 内容必须单独脱敏 | GitHub Pages 方案规则；本账户方案类型从接口读不到，需账户所有人在设置页确认 |
| 执行单推送 | 推送消息里的链接指向 Pages；Pages 下线后链接失效，推送本身不受影响 | 工作流 `DECISION_URL` |
| Actions 额度 | 私有仓库按分钟计费。实测每轮两个作业各约 40 秒，按作业向上取整约 2 分钟；每日 3 轮约 6 分钟，每月约 130 分钟，另加 CI。免费方案每月 2000 分钟，够用但需要监控 | 10/16 盘后运行记录 |
| 资金雷达发布 | `moneyRadar/publish.ts` 用 raw.githubusercontent.com 匿名读取，改私有后失效 | 源码 |
| 服务器定时任务 | `update-snapshot.sh` 匿名 `git fetch`，改私有后失效（该任务本已计划停用） | `scripts/schedule-server.sh` |
| 生产验收 | 10/19 的验收步骤包含 Pages 页面核对。验收期间改私有，会让验收无法完成，也会混淆"失败原因" | 生产验收清单 |

### 3.3 与 10/19 生产验收的时间冲突

- 北京时间 10/19 07:00 的盘前执行单是验收首轮，会按现有流程把执行卡（含总资产与峰值）提交回公开分支，13:30、15:40 两轮同理。
- 如果在验收前停掉提交或改私有，需要改动工作流或仓库设置，违反"验收前不推送新代码"，也会让验收结果无法解释。
- 处理：10/19 三轮按原流程运行，作为有记录、限时的例外。例外仅限生产执行卡这一处既有输出；除此之外，不再向公开仓库提交任何新的精确财务数据，包括本代理的文档和分支。验收结果出来后，第一项工作就是分离方案。

### 3.4 当前已执行的控制措施（不影响生产）

1. 本代理的评估稿已去除绝对金额，本裁定记录不含绝对金额。PR #38 描述同步去除。
2. 本代理此后提交的文档、分支、PR 描述一律只写比例、状态与日期。
3. 不新建含账本副本的分支。

### 3.5 分离方案的候选（待账户所有人确认方案类型后选定）

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| 甲：主仓库改私有，另建公开站点仓库 | 程序、账本、历史全部留在私有仓库；生产流程生成脱敏产物，推送到一个新建的、历史干净的公开仓库，由它发布 Pages | 公开面从零开始，历史中没有金额；不必改写主仓库历史 | 需要一个跨仓库推送令牌（放在 Secrets）；工作流要改 |
| 乙：主仓库保持公开，账本移出并改写历史 | 账本移到私有存储；用历史改写工具清除全部分支历史中的金额后强制推送 | 地址不变 | 36 个分支都要改写；PR 的引用（refs/pull）无法由强制推送清除，需联系 GitHub 支持；已存在的外部副本无法收回；风险高、范围大 |
| 丙：主仓库改私有，Pages 改为付费方案继续发布 | 升级付费方案，私有仓库继续发布 Pages | 改动最少 | Pages 仍公开，仍需脱敏；历史在私有仓库中不再公开 |

建议：甲。它同时满足"先控制当前访问"（主仓库私有）和"公开只发布审查过的必要信息"（站点仓库只有脱敏产物）。是否还需要清理历史，在主仓库改私有之后再评估：私有之后，历史只对有权限的人可见。

脱敏的口径：公开产物只保留比例、状态、日期、规则结论。去除总资产、峰值、市值、现金、股数、成本、参考价、成交金额。推送消息只发给委员会，是否保留金额另行裁定。
