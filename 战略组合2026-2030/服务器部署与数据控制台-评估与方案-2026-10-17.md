# 服务器部署与数据控制台：评估与方案（2026-10-17）

状态：评估稿，供委员会审议。本文不改任何代码、阈值与规则；生产分支 `cursor/account-snapshot-1009-c819` 保持 30e9dc02，10/19 生产验收之前不推送新代码。下文所有"改动"均为验收通过之后的计划。

## 一、结论先行

1. 程序已经具备上服务器的条件，但现在有两条互不相通的发布线：GitHub Actions 出执行卡并发布到 GitHub Pages，阿里云 ECS（hhwealth.cc）则由服务器自己的 cron 生成驾驶舱快照。两边跑的代码分支不同，数据时刻也不同。上服务器的第一件事不是装新东西，而是确定一个唯一的生成源。
2. 推荐方案 A：生成留在 GitHub Actions（有运行日志、有 run_id、结果提交回 git，可审计），服务器只做三件事：拉取已生成且已验证的产物、提供只读页面和只读数据接口、做镜像备份与健康监控。服务器不再独立计算任何生产结论。
3. 数据控制台按"生产 / 研究 / 模拟 / 治理"四层重组，共 10 个页面。页面上的每一个数字都带一个统一的"依据"信封，写明数值、来源、取数时刻、计算方法（含代码位置与提交号）、上游证据编号和数据状态（正常 / 过期 / 缺失 / 代理）。缺失显示为"缺失"，不显示为 0。
4. 每个页面增加"数据"标签页，可以直接看到页面背后的原始 JSON、表格、文件哈希和生成日志，并能下载。
5. Agent 交流统一成一种"Agent 包"格式，分三档复制：复制本卡、复制本页、复制今日全量。另有稳定链接 `/agent/*.md` 和一份清单 `/agent/index.json`，其他 Agent 可以直接拉取。
6. 有一项必须先由委员会裁定再上线：驾驶舱快照 `today.json` 含持仓市值（`marketValue`）和外部资金金额等绝对金额字段。8/15 已取消访问密码，等于这些字段对公网可见。正式上线前需要在"加访问控制"和"公网版只出百分比"之间二选一（见第九节第 1 项）。

## 四、服务器与域名：目标架构

### 4.1 方案比较

| | 方案 A（推荐）：Actions 生成，服务器发布 | 方案 B：服务器生成一切 | 方案 C：服务器作为 Actions 自托管运行器 |
|---|---|---|---|
| 生产结论在哪里算 | GitHub Actions，与现在一致 | 服务器 cron | 服务器，但由 Actions 调度并记录 |
| 可审计性 | 高：run_id、日志、提交回 git | 低：日志只在服务器本地 | 高 |
| 对 10/19 验收的影响 | 无，生产链路不变 | 大，要重新验收 | 中，需要重新验收运行环境 |
| 国内取数 | 依赖 GitHub 机房访问国内行情，已在跑 | 好 | 好 |
| 服务器访问 GitHub | 只需拉取产物，可改为从 Pages 或对象存储拉 | 需要拉代码，已出现过 fetch 挂起 | 需要稳定连接 GitHub |
| 复杂度 | 低 | 中 | 高 |

方案 A 的理由：生产链路已经在 Actions 上跑通并进入验收，换生成地点就要重新验收。服务器的价值在于展示、接口和备份，不在重复计算。如果日后发现 Actions 访问国内行情不稳定，再评估方案 C。方案 C 保留 Actions 的审计记录，只把执行机器换成服务器。

### 4.2 服务器规格与系统

- 规格：2 核 4G、40G 系统盘以上即可。现有 ECS 39.104.86.200 可以继续用。前端构建可在 Actions 完成，服务器不需要编译。
- 系统：Ubuntu 22.04 LTS。Node 20 LTS（与 CI 一致），nginx，certbot。第一期不装 MySQL。
- 账户：建专用用户 `honghu`，应用文件归它所有；nginx 以 `www-data` 只读访问站点目录。
- 地域与备案：服务器在中国大陆，域名解析到它并开放 80/443，就需要 ICP 备案，并在网站开通后 30 日内办公安联网备案。hhwealth.cc 已在这台 ECS 上提供 HTTPS 服务，需要确认备案号是否在有效期、主体与网站名称是否一致。如果改用香港或海外服务器，可以免备案，但国内访问速度和稳定性要实测。

### 4.3 域名与路径规划

建议一个主域名下按路径区分，减少证书和跨域问题：

| 路径 | 用途 | 缓存 |
|---|---|---|
| `/` | 数据控制台（人看） | HTML 不缓存；`/assets/*` 带哈希，缓存 30 天 |
| `/data/*` | 页面读取的 JSON 原件 | no-store |
| `/agent/*.md`、`/agent/index.json` | Agent 包与清单（模型读） | no-store |
| `/api/v1/*` | 只读数据接口：查询历史、按编号查证据、按日期查卡片 | 短缓存 60 秒 |
| `/health`、`/status.json` | 健康页：当前版本、各数据集最新时刻、是否过期 | no-store |

如果委员会希望把人看的页面和机读数据分开，也可以用子域名 `data.hhwealth.cc` 专门放 `/data`、`/agent`、`/api`，这时需要在 nginx 上为子域名单独签证书并配置 CORS。

hhwealth.cc 根路径过去跑着 2026-02 部署的老版鸿鹄理财（见 `scripts/package-deploy.mjs` 注释），现在 `deploy-ecs.sh` 默认发布到根路径 `/var/www/tios`。上线前要先确认根路径现在是哪个应用，老应用是否还需要保留。

### 4.4 目录结构与发布方式

```text
/opt/honghu/
  releases/<发布标签>/        每次发布一个目录，只读
    site/                     前端构建产物
    data/                     today.json、money.json 等
    agent/                    Agent 包与 index.json
    MANIFEST.json             本次发布包含的每个文件、SHA-256、来源 run_id、代码提交号
  current -> releases/<发布标签>   符号链接，切换即上线，改回即回滚
  archive/                    share/ 的完整镜像（git clone，只追加）
  api/                        只读接口代码
/var/www/honghu -> /opt/honghu/current/site
```

发布流程（方案 A）：

1. Actions 盘后任务完成并通过审计后，打一个发布标签，例如 `pub-2026-10-20-post`，把产物打包上传（GitHub Release 附件或阿里云 OSS）。
2. 服务器上的 systemd timer 每 5 分钟检查一次最新发布标签。发现新标签就下载，逐个校验 `MANIFEST.json` 中的 SHA-256，校验通过才解压到 `releases/`，然后切换 `current` 链接。
3. 校验失败就不切换，保持上一版，并通过 PushPlus 告警。不会出现半新半旧的页面。
4. 回滚：`ln -sfn releases/<上一标签> current`，一条命令。生产验收的回滚点 `prod-verified-2026-10-16-post` 可以直接对应到一个发布目录。

这样服务器不再需要 `git fetch` 代码分支，P2 问题自然消失。服务器访问 GitHub 不稳定时，可以改由 Actions 推送到 OSS，服务器从同地域 OSS 拉取。

### 4.5 进程与服务

| 服务 | 管理方式 | 监听 | 说明 |
|---|---|---|---|
| nginx | systemd | 80/443 | 强制 HTTPS、HSTS、noindex、SPA 回退、限速 |
| 只读接口 `honghu-api` | systemd（`Restart=always`） | 127.0.0.1:3001 | 只读 `/opt/honghu/current` 与 `archive`，不连数据库，不接受写入 |
| 发布拉取 `honghu-pull.timer` | systemd timer | 无 | 下载、校验、切换、告警 |
| 证书续期 | certbot 自带 timer | 无 | 续期后 reload nginx |
| 外部监控 | 第三方拨测或 Actions 定时任务 | 无 | 每 10 分钟拉 `/status.json`，过期就告警 |

现有 Express 后端里的写入类路由（`POST /api/portfolio/positions`、`POST /api/tios/run`、注册、登录）第一期不对公网开放。nginx 只转发 `/api/v1/` 下的只读路由。

### 4.6 安全

- SSH：只允许密钥登录，禁用密码和 root 登录；可选改端口；装 fail2ban。
- 防火墙：阿里云安全组和 ufw 都只开 22（限来源 IP）、80、443。
- nginx：`limit_req` 按 IP 限速；隐藏版本号；`X-Robots-Tag: noindex`（已有）；CSP 只允许本站资源。
- 密钥：PushPlus 等令牌只放在 GitHub Secrets 和服务器的 `/etc/honghu/env`（权限 600），不进仓库，不进前端构建。
- 访问控制：取决于第九节第 1 项裁定。如果加访问控制，建议用 nginx 的 basic auth 或一个固定访问令牌，不重新启用后端的 MySQL 登录体系。

### 4.7 备份与监控

- 备份：`share/` 已在 git 中，只追加，本身就是一份备份；服务器 `archive/` 再镜像一份。每日把 `releases/` 最近 30 个目录打包上传 OSS，保留 180 天。
- 健康页 `/status.json` 列出每个数据集的 `asOf`、`generatedAt`、预期更新频率、是否过期、来源 run_id 和代码提交号。现有 `check-live.mjs` 改为读这个文件，判定更简单。
- 告警只报"数据过期、校验失败、服务不可用"三类，走现有 PushPlus 通道。按既有规定，告警只触发复核，不触发仓位动作。

### 4.8 分步部署清单（验收通过后执行）

1. 确认备案状态与根路径现状；委员会完成第九节裁定。
2. 服务器加固：建 `honghu` 用户、SSH 密钥、ufw、fail2ban。
3. 安装 Node 20、nginx、certbot；签发或沿用 hhwealth.cc 证书。
4. 建 `/opt/honghu` 目录结构；写 nginx 站点配置，按 4.3 的路径与缓存规则。
5. 停用旧的 `update-snapshot.sh` cron（`scripts/schedule-server.sh uninstall`），避免旧分支继续写数据。
6. 在 Actions 增加"打包发布"步骤：生成 `MANIFEST.json`，打标签，上传产物。
7. 部署 `honghu-pull.timer`；手动触发一次，核对页面与 Pages 上的执行卡逐字节一致。
8. 部署只读接口 `honghu-api`；nginx 放开 `/api/v1/`。
9. 部署 `/status.json` 与外部拨测；故意停一次拉取，确认告警能到。
10. 演练一次回滚，确认切回上一发布目录后页面立即恢复。

每一步完成后，以线上实际结果为准，记入验收文档，不以本地自检通过代替。

## 五、数据控制台：页面信息架构

### 5.1 总原则

- 分层标识：每个卡片左上角标明所属层，生产 / 研究 / 模拟 / 治理，四种固定颜色。研究层和模拟层卡片统一带一行"只观察，不进执行卡"。
- 不做综合分：页面不出现任何加总打分。多个指标并列显示，不合成一个数。
- 缺失就写缺失：拿不到的数据显示灰色"缺失"和原因，不显示 0、不显示上一期数值冒充当期。
- 过期就写过期：每个数据块右上角显示"截至 X 日，已 N 天未更新"，超过预期频率就变成黄色。
- 只出百分比：公网版本不出绝对金额，裁定之前按这一条执行。
- 判断先于结果：凡是带判断的页面（CY-01 研判、复核结论），显示记录时刻和对应的证据包哈希，让人能看出判断是在看到结果之前留下的。

### 5.2 页面清单

| 页面 | 路径 | 层 | 主要内容 | 数据来源 |

### 5.3 卡片的统一结构

每张卡从上到下固定为五段：

1. 结论一行：这张卡说了什么，用一句完整的话。
2. 数据表：具体数值。每个数值都可以点开"依据"。
3. 口径说明：这个数怎么算的，参数是多少，参数是谁在哪天定的。
4. 不能推出什么：例如"背离不等于卖出信号"。研究层和模拟层的卡片必须有这一段。
5. 底部：数据截至时刻、生成时刻、代码提交号、复制按钮。

## 六、每个数字都有依据：依据信封

### 6.1 字段

所有对外输出的数值统一包成下面的结构。现有产物先在发布时由适配器补齐，再逐个模块改为原生输出。

```json
{
  "id": "L4-05:R-01:SEMI_EQUIP",
  "label": "半导体设备 资金代理变量 20 日变化",
  "value": 0.032,
  "unit": "ratio",
  "display": "+3.2%",
  "layer": "研究",
  "status": "OK",
  "asOf": "2026-10-16",
  "fetchedAt": "2026-10-16T07:52:10Z",
  "source": { "id": "tencent-kline", "name": "腾讯行情 日K", "ref": "接口地址或文件路径" },
  "method": {
    "id": "moneyRadar.metrics.change20",
    "formula": "近 20 个交易日成交额均值 / 前 20 个交易日均值 - 1",
    "code": "backend/src/services/moneyRadar/metrics.ts@<提交号>",
    "params": { "window": 20 },
    "paramsRuledAt": "参数由委员会哪天裁定，未裁定写 PENDING"
  },
  "inputs": ["上游数据的 id 列表"],
  "notes": "代理变量，不是真实资金流"
}
```

`status` 只取四个值：`OK`（正常）、`STALE`（超过预期更新频率）、`MISSING`（拿不到，必须写原因）、`PROXY`（用代理变量替代）。这四个值来自 CY-01 证据包已在用的口径，前端据此决定颜色。

### 6.2 页面上怎么显示

- 点开任一数字，右侧抽屉显示信封里的全部字段。
- `inputs` 可以逐级点开，一直追到原始取数。
- `method.code` 链接到 GitHub 上对应提交的那一行代码。
- 参数显示 `PENDING` 的，抽屉顶部提示"参数未经委员会裁定"。CY-01 现有 30 个待裁定参数就属于这种情况。

### 6.3 机械检查

在现有审计里增加一项：发布包中所有数值都必须有完整信封，`MISSING` 必须写原因，`method.code` 必须指向存在的文件。缺一项，发布失败。这样"有根有据"由程序检查，不靠人看。

## 七、页面背后的数据

每个页面右上角有"数据"标签页，内容固定为：

| 区块 | 内容 |
|---|---|
| 原始文件 | 页面读取的 JSON 原件，可折叠浏览，可搜索字段 |
| 表格视图 | 把 JSON 中的数组展开成表格，可排序、筛选，可下载 CSV |
| 文件身份 | 文件路径、SHA-256、生成时刻、来源 run_id、代码提交号 |
| 生成日志 | 本次生成的关键日志行：取数成功或失败、跳过原因、闸门判定 |
| 历史版本 | 同一文件过去 30 个发布的列表，可以任选两期对比差异 |

只读接口 `/api/v1/` 提供同样的东西给程序使用：

- `GET /api/v1/datasets`：所有数据集清单与新鲜度。
- `GET /api/v1/datasets/{name}?asOf=2026-10-16`：某个数据集某一天的版本。
- `GET /api/v1/evidence/{id}`：按编号取一条证据及其上游。
- `GET /api/v1/decision/{date}/{session}`：某天某时段的执行卡。
- `GET /api/v1/diff/{name}?from=…&to=…`：两期差异。

## 八、一键复制给其他 Agent

### 8.1 Agent 包格式（统一）

```text
# 鸿鹄理财 Agent 包：<范围名称>
范围：<本卡 / 本页 / 今日全量>　层：<生产 / 研究 / 模拟 / 治理>
数据截至：2026-10-16 15:47（北京时间）　生成：<时刻>　代码：<提交号>
文件哈希：<SHA-256>　原件：https://<域名>/data/<文件>.json

使用约束（必须原样转述）：
- 本包只提供数据与依据，不构成买卖指令。
- 买入权限关闭。实盘卖出规则只有 C级清退、单票归位、熔断三项。
- 研究层与模拟层内容只观察，不进执行卡。
- 缺失项就是缺失，请勿补全或推测。

## 结论
## 数据表（每行带 id、数值、状态、截至时刻、来源）
## 口径与参数
## 缺失与过期
## 不能推出什么
## 请按以下格式回复（便于回收）
```

最后一段"回复格式"让对方 Agent 按固定结构回答：引用了哪些 id、结论、依据、不同意之处。回复只作为研究意见存档，不能改动规则、阈值或名单。

### 8.2 三档复制

| 按钮 | 位置 | 内容 | 体量 |
|---|---|---|---|
| 复制本卡 | 每张卡底部 | 这张卡的结论、数据表、口径 | 约 1–3 千字 |
| 复制本页 | 每页右上角 | 本页全部卡片 + 本页缺失清单 | 约 5–15 千字 |
| 复制今日全量 | 总览页 | 所有页面的结论与关键数据表，详表给链接 | 控制在 30 千字以内，超出部分只给链接 |

复制前先在页面上预览要复制的文字，确认后才写入剪贴板。复制内容和 `/agent/*.md` 的稳定链接是同一份文件，避免出现两个版本。

### 8.3 稳定链接与清单

- `/agent/today.md`：今日全量。
- `/agent/<页面名>/latest.md`：各页最新版。
- `/agent/<页面名>/<日期>.md`：历史版本。
- `/agent/index.json`：所有 Agent 包的清单，包括名称、范围、截至时刻、哈希和链接。其他 Agent 先读这一个文件，就知道还能拉什么。

现有 `today.agent.md`、`money.agent.md`、执行卡 agent 包保留原链接一个过渡期，内容改为新格式。
